## Inter-lens conflicts (all resolved without trade-offs)

- **Architecture strength #3 ('validation protocol... Do not change this') vs methodology/adversarial amendments (STAT-7, STAT-11, ADV-3 §2.1, ADV-4)**
  - *Issue:* The architecture lens directs that the validation protocol ship verbatim, while the other two lenses require four changes to it: cluster-bootstrap specification, frame enrichment and human class-labeling, rater-independence tightening, and a rubric-defect escape field on the rating instrument.
  - *Resolution:* Not a real contradiction once scoped: the architecture praise targets the metric design core (two-stage decomposition, AC1 alongside kappa, both-direction absence errors, dev-set labeling) and all four amendments are additive specifications that leave that core untouched. Adopt the amendments as protocol completion, not redesign; treat the metric core as frozen consensus (see consensus_strengths).
- **Precision-first / recall-never-gated detector philosophy (architecture strength #4, adversarial strength #5) vs evidence-conditioned gating (STAT-1, STAT-2, STAT-4)**
  - *Issue:* The praised detector philosophy explicitly never gates on recall, but the methodology fixes make rubric gates (S4 N/A, S6/S8 essentialness, BF mandatory_when) key on detector evidence — so a missed detection now silently flips badge-relevant applicability and essentialness in the lenient direction, which absence-FPR cannot see.
  - *Resolution:* Keep precision-first as the detector ship gate — it is correct for a grounding layer. Resolve the tension at the gating layer instead: every evidence-conditioned gate must fail strict on missing evidence ('unstated' ⇒ applicable-with-caveat; absence of a sampler mention never auto-excuses S4), and the M7 report must record (not gate) recall for the specific detector families that feed gates (method_mention, sampler_config, BF mention, model-count). This preserves both lenses' positions.
- **ARCH-1 verification (demoted: evidence refs are stable, normal schema work suffices) vs STAT-2 (contract change required: score() lacks Evidence[])**
  - *Issue:* The architecture verifier concluded ScoredResult's by-reference evidence is safe enough to defer to routine M1 schema authoring, while the methodology finding requires evidence-derived inputs to reach f's score() as a pre-M5 contract change — two different answers to 'does evidence representation need a contract decision now?'
  - *Resolution:* Both are satisfied by one decision: add the compact gate-facts object (inference_method, n_models, bf_claimed, prior_informativeness) to §4.3 at M1, embedded in ScoredResult. f re-derives evidence-conditioned gates from gate-facts (deterministic, no raw Evidence[] needed), and ScoredResult becomes self-describing enough for the round-trip claims without full by-value copying. The remaining ARCH-1 identity fields ride along as fix-during schema work.
- **Fixture-driven decomposition as untouchable strength (architecture #1, adversarial #1) vs ADV-5 (committed fixture PDFs are license violations)**
  - *Issue:* The most-praised architectural mechanism — committed recorded fixtures at every boundary — collides with the verified finding that a-ingest's plan to check PDF blobs into the repo bakes copyright violations permanently into git history.
  - *Resolution:* Preserve the testing architecture, change only the storage mechanism: committed fixtures are fine for schema-instance JSON (ParsedDoc, Evidence, ScoredResult) derived from genuinely CC-BY/CC0 sources recorded in a license manifest; PDF bytes and full-text of anything else are fetch-by-script with sha256 pinning, mirroring the rule the validation protocol already applies to goldset documents. The decomposition's testability is untouched.

The plan set is implementable as designed and implementation can begin: the spine + 8 subplans + protocol form a coherent, well-sequenced architecture with real decoupling machinery (contract-first schema, stubs, recorded fixtures, web-free core seam) and no milestone-order inversions. **Strengths identified:**

### ARCH-1 [pre-implementation → verified: fix-during, holds=True]
